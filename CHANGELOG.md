**fix(application): align the resilience and aggregate contracts across arms (#214)**

 * The two arms did different work on /resilience and /aggregate, so the load-test
 * comparison of those endpoints was invalid.
 * /resilience:
 * - Both arms now call /api/data?delayMs&#x3D;N and consume the body as an opaque string
 * (the imperative arm no longer sleeps locally; the reactive arm no longer requires JSON)
 * - Same bodies: OK:&lt;Module&gt;:Resilience:&lt;body&gt;:&lt;thread&gt; and FALLBACK:&lt;Module&gt;:Resilience:timeout
 * - delayMs is sent only when greater than zero, so the default call takes the undelayed route
 * /aggregate:
 * - Both arms consume the body as an opaque string, combined in id order 1,2,3
 * (the reactive arm no longer parses JSON or prefixes itemN:, and mergeSequential
 * replaces merge so the order no longer depends on completion order)
 * Bundled stub:
 * - The delayMs route applies a fixed numeric 1500 ms instead of a uniform 100-2000 ms
 * random delay. Templating the delay is not possible: WireMock deserialises
 * fixedDelayMilliseconds as an integer and its response-template transformer never
 * templates the delay, so a templated value fails at server startup. Applied to all
 * three copies (compose, k8s configmap, cloudformation heredoc)
 * Tests, specs and docs:
 * - Resilience and aggregate tests rewritten for the new contracts, covering success
 * and fallback in both modules
 * - The aggregate spec no longer claims the imperative fan-out executor is never closed;
 * it documents the shared executor created once and closed on shutdown
 * - Bruno examples updated; the resilience collections drop delayMs so the example
 * matches the success body it shows
 * - K6 adds a fallback probe per arm and raises preAllocatedVUs to 6000
 * - Gatling javadoc and the readme delay figures corrected
